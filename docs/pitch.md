# ONTHEGO 3-minute pitch

개발자는 작업 장소만 바꾸는 것이 아닙니다. Codex에서 Cursor로, 다시 Claude나 Hermes로 도구를 바꿉니다. 이때 코드 자체보다 더 자주 끊기는 것은 에이전트가 알고 있던 맥락입니다. 무엇을 시도했는지, 왜 실패했는지, 다음에 무엇을 해야 하는지가 각 도구와 머신에 흩어집니다.

ONTHEGO는 이 문제를 다섯 개의 명령으로 해결합니다. `init`, `login`, `pass`, `status`, `pull`입니다.

시작은 `onthego init`입니다. 현재 Git 저장소에 안전한 프로젝트 ID와 기본 동기화 설정을 만들고 로컬 시크릿과 상태 파일을 Git에서 제외합니다. 같은 저장소에서 다시 실행해도 기존 프로젝트 ID를 유지합니다.

핵심 데모는 `onthego pass` 한 줄입니다. 사용자가 에이전트 이름이나 세션 ID를 고를 필요가 없습니다. ONTHEGO가 현재 Git 프로젝트를 기준으로 Codex, Cursor, Hermes, Claude를 모두 스캔합니다. 발견한 관련 세션을 전부 모으고 로컬에서 시크릿을 제거한 뒤, 작업 요약과 함께 Daytona로 전달합니다.

Daytona에서는 전달받은 컨텍스트로 `agent-sync` 작업을 실행합니다. 실행 상태와 로그, 산출물 영수증은 Contabo의 경량 컨트롤 플레인을 통해 다른 로컬 환경과 동기화됩니다. 저장소의 실제 시크릿은 루트 `.env`에만 남고, 에이전트 로그는 전송 전에 필터링됩니다.

`onthego status`는 지금 어디에서 무엇이 실행 중인지 보여줍니다. 여기에 GPT-5.6 Luna의 high reasoning 요약을 붙여 긴 로그를 읽지 않아도 현재 상태와 다음 행동을 알 수 있게 했습니다.

마지막으로 `onthego pull`은 Daytona 결과의 SHA-256이 실행 영수증과 일치할 때만 파일을 받습니다. 그래서 팀원은 다른 머신에서도 로그인한 뒤 같은 작업 상태를 확인하고 검증된 결과를 이어받을 수 있습니다.

Phase 1의 가치는 단순합니다. 어떤 코딩 에이전트를 쓰든 `onthego pass` 한 줄로 작업 맥락을 안전하게 옮기고, `status`로 이해하고, `pull`로 이어서 작업합니다.

GPU 파인튜닝과 모델 서빙, Hugging Face 커넥터는 다음 단계입니다. Daytona의 GPU 인프라 위에서 동일한 컨텍스트와 상태 동기화 방식을 확장할 예정입니다.
